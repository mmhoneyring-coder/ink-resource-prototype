# Balance Runner

ゲーム本体とは分離した、Ink Resource Prototype 用のバランス検証ランナー。

## 現在できること

- 現在の `app.js` と同じスプラッシュ生成パラメータで大量試行
- 180×280 / 220×360 / 240×420 / 260×450 の盤面比較
- スプラッシュの狙い方（全体、下→上、各層集中、ランダム）の比較
- 円形資源の命中、筆経路での追加発見、有効化数を集計
- START位置、筆半径、仮の筆距離予算を変更可能
- 仮の点数・情報状態を付け、最終得点を集計
- 5種類の筆取得方針を同条件で比較
- 各ランの上層／中層／下層について「何ptが何枚」を表示
- 得点帯に応じて資源の当たり判定サイズを5段階に変更
- 50ptお宝のスプラッシュ接触率・筆途中発見率・最終取得率を集計

## 現在の第一候補

暫定値として以下をブラウザ版の初期値にしている。

- 盤面: 240×420
- 通常資源数: 40
- 特別お宝: 50pt ×1を別枠で追加
- スプラッシュ: 8回
- 筆距離予算: 480
- 筆半径: 2
- START: 上から78%
- 最終有効化数の目安: 6〜10個程度

10個を必達・固定値にはせず、ランや戦略によって6〜10程度に散る状態を当面の評価目安にする。

## 仮の点数・情報状態

正式仕様ではなく、戦略差を見るための仮置き。

- 通常40枚の約20%: 位置と得点が最初から見える
- 通常40枚の約20%: 位置は見えるが得点は `?`
- 通常40枚の残り約60%: インクが触れるまで存在も見えない
- 見えている資源の1つを必ず12ptにし、中層付近の擬似ゴールにする
- 50ptのお宝は通常40枚とは別に1枚追加し、中層または下層のどちらかへ完全隠しで置く
- 通常点候補
  - 下層: 1 / 2 / 3 / 4 / 5 / 6 / 8
  - 中層: 3 / 4 / 5 / 6 / 7 / 8 / 10 / 12
  - 上層: 6 / 8 / 10 / 12 / 14 / 16 / 20
- 上ほど通常点の期待値が高い

通常点候補と各層枚数はまだ正式決定ではない。

## 仮の資源サイズ

240×420での当たり判定半径を、通常5段階＋お宝専用サイズとして仮置きする。

| 得点帯 | 半径 |
| --- | ---: |
| 1〜3pt | 5.0 |
| 4〜6pt | 4.3 |
| 7〜10pt | 3.7 |
| 12〜16pt | 3.1 |
| 20pt以上 | 2.6 |
| 50ptお宝 | 1.8 |

高得点ほどスプラッシュや筆の偶然接触で見つかりにくくする。複数の点数が同じサイズ帯を共有するため、サイズだけで正確な点数は確定しない。

## 仮の筆モデル

筆はSTARTおよび既存の筆線を接続網として扱い、選択した資源へ直線で伸ばす。線の途中で完全隠し資源に触れれば、その場で発見＋接続済みなので有効化する。

現在比較できる取得方針:

1. `nearest`: 近い順
2. `valueRate`: 点数 / 距離。得点不明はその層の通常点平均で仮評価
3. `highValue`: 高得点を強く優先
4. `upper`: 上層を優遇
5. `goalFirst`: 最初に見えている12pt擬似ゴールを優先

これは人間の最適行動を再現する完成AIではなく、**どの方向の戦略が現状の点数設計で得をしやすいかを比較するヒューリスティック**。

## ブラウザ

GitHub Pages の `/runner/` から実行できる。

## CLI

```bash
node runner/run.mjs --trials 500 --splashes 8 --strategy wide
```

CLIはまだ旧来の探索・命中率中心。点数・筆方針の比較はブラウザ版で行う。
