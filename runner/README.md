# Balance Runner

ゲーム本体とは分離した、Ink Resource Prototype 用のバランス検証ランナー。

## 現在できること

- 現在の `app.js` と同じスプラッシュ生成パラメータで大量試行
- 180×280 / 220×360 / 240×420 / 260×450 の盤面比較
- スプラッシュの狙い方（全体、下→上、各層集中、ランダム）の比較
- 円形資源の命中、筆経路での追加発見、有効化数を集計
- START位置、筆半径、仮の筆距離予算を変更可能
- 仮の点数・情報状態を付け、最終得点を集計
- 5種類の筆取得方針を同条件で比較
- 得点帯に応じて資源の当たり判定サイズを5段階に変更
- 50ptお宝の取得率を集計
- `fixed-deck-sim.mjs` で層ごとの枚数と点数内訳を固定した検証が可能

## 現在の第一候補

- 盤面: 240×420
- 通常資源数: 40
- 特別お宝: 50pt ×1を別枠で追加
- スプラッシュ: 8回
- 筆距離予算: 480
- 筆半径: 2
- START: 上から78%
- 最終有効化数の目安: 6〜10個程度

## 固定デッキ検証（仮）

層ごとの通常資源数を **上14 / 中13 / 下13 = 40枚** に固定し、公開情報として扱える形で点数内訳も固定する。

| 層 | 内訳 | 合計点 | 1枚平均 |
| --- | --- | ---: | ---: |
| 下層 | 2×2, 3×2, 4×2, 5×2, 6×2, 8×3 | 64 | 4.92 |
| 中層 | 6×2, 8×2, 10×2, 12×3, 14×2, 16×2 | 144 | 11.08 |
| 上層 | 14×2, 16×2, 20×3, 24×3, 28×2, 30×2 | 308 | 22.00 |

50ptのお宝はこの40枚とは別の41枚目として、中層または下層に50%ずつで追加する。見えている擬似ゴールは中層の12ptのうち1枚を使うため、通常デッキの総枚数・総得点は変わらない。

実行:

```bash
node runner/fixed-deck-run.mjs 600
```

`fixed-deck-run.mjs` は、近い順 / 点数÷距離 / 高得点優先 / 上層寄り / 見える当たり優先を同一条件で比較し、有効化数、最終得点、50pt取得率、層別の取得数と得点を出力する。

## 仮の情報状態

- 通常40枚の約20%: 位置と得点が最初から見える
- 通常40枚の約20%: 位置は見えるが得点は `?`
- 通常40枚の残り約60%: インクが触れるまで存在も見えない
- 中層12ptの1枚を必ず完全公開し、擬似ゴールにする
- 50ptお宝は完全隠し

## 仮の資源サイズ

240×420での当たり判定半径を、通常5段階＋お宝専用サイズとして仮置きする。

| 得点帯 | 半径 |
| --- | ---: |
| 1〜3pt | 5.0 |
| 4〜6pt | 4.3 |
| 7〜10pt | 3.7 |
| 12〜16pt | 3.1 |
| 20pt以上 | 2.6 |
| 50ptお宝 | 1.8 |

高得点ほどスプラッシュや筆の偶然接触で見つかりにくくする。複数の点数が同じサイズ帯を共有するため、サイズだけで正確な点数は確定しない。

## 仮の筆モデル

筆はSTARTおよび既存の筆線を接続網として扱い、選択した資源へ直線で伸ばす。線の途中で完全隠し資源に触れれば、その場で発見＋接続済みなので有効化する。

現在比較する取得方針:

1. `nearest`: 近い順
2. `valueRate`: 点数 / 距離。得点不明はその層の公開デッキ平均で仮評価
3. `highValue`: 高得点を強く優先
4. `upper`: 上層を優遇
5. `goalFirst`: 最初に見えている12pt擬似ゴールを優先

これは人間の最適行動を再現する完成AIではなく、どの方向の戦略が現状の点数設計で得をしやすいかを比較するための暫定ヒューリスティック。

## ブラウザ

GitHub Pages の `/runner/` から利用する。ブラウザ側の通常表示は検討中パラメータを触るための画面で、固定デッキ比較は現時点では `fixed-deck-sim.mjs` / `fixed-deck-run.mjs` を正とする。
